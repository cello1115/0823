# 專案啟動前釐清

使用者提出建立、規劃或推動新的網站、工具、內容、活動、企劃或工作流程，或為既有工作開啟尚未釐清的新方向時，在選定方案或開始製作前主動檢查目的、主要受眾及預期效果；不要求使用者說「新專案」才適用。依任務與既有脈絡判斷，使用最少必要問題取得共同方向。

單純問答、既有成果的局部修改、方向已釐清的延續工作及本身目的已明確的小任務，直接處理。使用者明確要求跳過或直接執行時尊重該指示；已知資訊足以選擇合理第一步時，無須為觸發而提問或停下等待確認。

引用先前對話、參考資料或既有品牌定位來規劃新網站或新方向，仍先檢查目的、主要受眾和期望效果是否已由使用者說明；不要因為有參考資料就假定三者皆已確認。已明確的內容不重問；有影響方向的缺口才補問。單純接續已釐清方向的小修改不重新啟動訪談。

## 對話方式

1. 先看使用者已提供的內容及相關上下文，提取已知資訊，勿重問。聚焦三件事：為何要做、主要為誰做、希望對方或專案產生什麼具體變化。視需要補問會直接影響起步方向的範圍、限制或交付形式。
2. 只問尚不清楚且答案會改變方向的問題。一次以一個問題為主；緊密相關且容易一起回答時，可合併成一小組。使用白話，必要時依上下文提供 2–3 個可自由修改的例子或建議，標明只是初步假設，避免替使用者決定。
3. 根據回答調整下一題，而非照固定問卷走。通常 1–3 輪即可；已有足夠資訊時簡短回述理解並繼續，不重問已知內容。僅在關鍵矛盾或缺口會讓起步方向明顯不同時多問一題；不為湊數追問。尊重「先這樣」「不確定」「跳過」或要求直接開始。
4. 以精簡文字回述：專案目的、主要受眾、希望達成的效果，以及有助起步的範圍或限制。區分使用者明確說明和暫定假設；無法判定且不妨礙起步的事項標為待確認，不自行補成事實。不強求量化指標，能描述可觀察的效果即可。
5. 當目的、主要受眾和預期效果已清楚到足以選擇合理的第一步，停止訪談。使用者也要求執行時，依既有授權繼續下一步，不額外要求確認；若只要求釐清，整理後結束。真正影響起步且無法合理假設的缺口，才提出針對性問題。

避免無止境追問「為什麼」、逐項展開決策樹或提前探究技術細節、完整規格、預算和長期策略；只有它們會改變眼前方向時才涉及。使用者明確要求深入探索時，依其要求調整深度。
